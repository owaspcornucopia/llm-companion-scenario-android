# Android threat coverage

This scenario deliberately implements **41 MobileApp Edition v2.0 cards**.
The source of
truth is the supplied
[`mobileapp-cards-2.0-en.yaml`](https://github.com/OWASP/cornucopia/blob/main/source/mobileapp-cards-2.0-en.yaml)
and its companion mapping files:
[`mobileapp-mappings-2.0.yaml`](https://github.com/OWASP/cornucopia/blob/main/source/mobileapp-mappings-2.0.yaml),
[`mobileapp-mastg-2.0.yaml`](https://github.com/OWASP/cornucopia/blob/main/source/mobileapp-mastg-2.0.yaml),
and
[`mobileapp-maswe-2.0.yaml`](https://github.com/OWASP/cornucopia/blob/main/source/mobileapp-maswe-2.0.yaml).

Every MobileApp card not in the implemented table is explicitly represented as
`applicable=false` and `implemented=false` in
[`ScenarioCatalog.java`](../app/src/main/java/org/owasp/pwnednext/android/scenario/ScenarioCatalog.java).
This is intentional scope control: a card is not silently implied to apply just
because the deck contains it.

## MobileApp cards explicitly not applicable

These are all MobileApp Edition v2.0 cards not selected for this scenario. They
are marked `Applicable: false` in the companion cheatsheet and
`applicable=false, implemented=false` in the Android catalog.

| Suit | Not-selected cards | Why this lab does not apply them |
| --- | --- | --- |
| Platform & Code | PCX, PCJ, PCK, PCA | No WebView or invented attack, and no deliberate outdated-platform or native memory-corruption exercise. |
| Authentication & Authorization | AA3, AA4, AA5, AA6, AAX, AAJ, AAK, AAA | No biometric prompt, keystore unlock flow, URL-scheme login, or separate authorization service. |
| Network & Storage | NSJ, NSX, NSQ, NSK, NSA | Inference is entirely on-device, so the scenario has no model network path, certificate-pinning, or custom TLS-trust implementation. |
| Resilience | RS6, RSK, RSA | No weak anti-debugging control exists to bypass, and no invented resilience attack is claimed. |
| Cryptography | CRM5, CRM8, CRMJ, CRMQ, CRMK, CRMA | Standard AES is used rather than obfuscation or custom cryptography; no separate fail-open or invented crypto path exists. |
| Cornucopia | CM2, CM3, CM4, CM5, CM6, CM7, CM9, CMJ, CMQ, CMK, CMA | No separate privacy-consent, notification, file-download, or content-distribution workflow. |
| Wild card | JOAM, JOBM | Open-ended compliance and surveillance cards are not represented by a specific control in this app. |

## Mitigation exercise

For each implemented card, testers should write a threat-model entry containing:

1. the sensitive asset (question, SQL, transaction row, memo, clipboard, intent,
   component, preference, or model prompt);
2. the trust boundary crossed (screen, clipboard, Logcat, SQLite, provider,
   file resolver, in-process model, or model output);
3. the observed attack step from the card page;
4. the MASTG/MASWE reference above; and
5. a proposed fix, such as `FLAG_SECURE`, redacted logging, least-privilege
   permissions, non-exported components, parameterized provider queries,
   canonical file paths, step-up authentication, authenticated storage,
   integrity checks, and emulator/tamper policy.
